## 5. Finding: composer stays dirty after a successful save — PRE-EXISTING

Navigating away after a successful "Save draft" raised a `beforeunload` "Leave
site?" dialog, even though the draft had been written to the database.

Root cause, `apps/web/src/components/project/composer.tsx:379`:

```ts
if (initialSignature.current === null) initialSignature.current = signature;
const dirty = initialSignature.current !== signature;
```

The baseline is captured once on first render and never refreshed after a save,
so the form is permanently dirty for the rest of its life once any field changes.

**Not a Phase 8 regression.** This is Phase 6 tranche A's A6 guard; Task 4 only
added `lookingFor` to the signature at line 365. Every other field exhibits it
identically. Line 383's `if (!dirty || saving) return;` does disarm the guard
during the save itself, so the save is never blocked — the symptom is only the
spurious prompt afterwards.

Left unfixed: out of scope for this phase, and fixing it means deciding what the
post-save baseline should be for a draft that stays on `/new`. Logged for triage.
